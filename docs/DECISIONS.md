# Decisions

## Phase 4

- 2026-10-27 · Director's call: skip the Phase 3 online-PvP work for now; Phase 4 is built on top of the AI-only Phase 2 architecture. Both sides of a match (the player's crew and the opposing team) are playable role compositions, with AI controlling whichever side the player doesn't. · No netcode/server, so this stays in `packages/sim` and `packages/client` only.
- 2026-10-27 · The playable Hunter role is framed as a freelance crew taking a contract _for_ the Syndicate instead of _for_ the Run, reusing the existing faction system (§2, §8.1) rather than inventing new lore. No retcon of Wren/Kade: they're freelancers, not loyal to one side. · Avoids a contradiction (same character fighting for and against the same cause) without adding IP-risk lore.
- 2026-10-27 · Director's call: no Fixer betrayal mechanic for now. The role's `broker` action is present in content as a stub whose effect text says it is disabled in AI-only play; nothing in the sim implements it. · Spec (§7.6) explicitly requires asking before enabling betrayal by default; there's also no second human team to betray yet.
- 2026-10-27 · **Rules conflict surfaced and resolved, not merged:** §7.2 says a character at neural capacity 100 gets _attenuation_ (−1 action every other tick for 3 ticks), but Wren's tested, golden-replay-locked rule is overload ≥100 = **Flatlined**, an end condition. Kept `wren.overload` exactly as-is (payload burnout → Flatlined, unchanged); added a new, separate `neural.capacity` constant (100) in `balance.json` for the Phase 4 budget system (implant slot cost + active ability cost), which will use the attenuation rule when implemented. The two meters are not merged. · Preserves the Phase 1/2 golden run and balance targets; the alternative (merging them) would silently change what "Flatlined" means.
- 2026-10-27 · Added `packages/content/data/roles.json` (6 role kits, §7.3) and `implants.json` (9 implants, §7.4), both Zod-validated (`rolesSchema`, `implantsSchema` in `schema.ts`). Numeric fields only exist where the spec states a number (e.g. Mask `loadCost: 10`); everything else is `effect`/`tradeoff` text, per CLAUDE.md "no magic numbers in logic" (none of these numbers drive sim logic yet — this slice is content-only).
- 2026-10-27 · Each role action has an optional `channel: 'meat' | 'net' | 'ghost' | null`. I initially added a hard validation requiring every role to cover all three channels from its base kit (reading §7.1 literally), then reverted it: the spec's own action tables don't support it — Courier's Sprint and Dead drop, Decker's Jack in/out, Receiver's Relocate and Read out are movement/logistics, not combat-triangle tools, so they're tagged `null`. Channel tags on combat/hack actions are my best reading of each action against the §7.1 definitions, not spec-stated; flag for review (notably Decker has zero Meat/Ghost tools in its base kit — §7.1's "at least one tool in each of the other two channels" presumably expects implants to round that out).
- 2026-10-27 · Decker's net-hack content entries (`blind`, `unlock`, `ice`, `burn`) reference the existing `balance.net.costs.*` numbers in their `effect` text instead of repeating the numbers, to avoid two sources of truth that could drift apart.
- 2026-10-27 · Director's call: "world map" means multiple playable districts (like Dock Row), not the Phase 5 territory/faction meta-layer (§8.2), which is held separately. Added `content.districts: readonly District[]` alongside the existing `content.district` (now just the default, `ironbridge-dock-row`, for callers that don't pick one). `MatchSetup.districtId` selects a district in `createMatch`; `buildRuleset` now takes `district`/`balance` directly instead of a whole `Content`, so it isn't tied to the default pick.
- 2026-10-27 · Added a second district, `harrow-yards.json` (a new map, built and verified rather than a reskin, per the director). It's a real design task, not just data entry — I made a mistake worth recording: my first two geometry attempts gave identical BFS route lengths locked vs open (doors provided no actual shortcut, defeating their purpose), because the "long way" and the door route happened to cost the same number of moves. Fixed by moving the single non-door connector far from the receiver (forcing a real detour) and putting the receiver close to one door (a genuine shortcut) — verified with a plain BFS independent of the sim before writing the final JSON, then re-verified through the real sim (`distField`), giving 25 moves locked / 17 open (same numbers as Dock Row, coincidentally — a different map, not a copy).
- 2026-10-27 · `districtSchema` gained two structural checks while editing it for the second district: every hunter must start on a passable tile, and the receiver must be BFS-reachable from `wrenStart` with every door treated as open (a connectivity sanity check, not a route-length check). Both caught real mistakes in my own hand-authored test mutations, so I'm confident they'll catch a genuinely broken map before it ships.
- 2026-10-27 · Cut Harrow Yards from 3 hunters to 2 after verifying play-through, not just schema validation: 3 hunters (one patrolling the only corridor Wren must cross) gave 0/20 deliveries across every payload size with the project's existing greedy bot, even Light. Verified that was a real gauntlet, not a tooling bug, by tracing ticks by hand before cutting a hunter. Also surfaced a bug in my own throwaway verification script along the way (a hardcoded Kade action script copied from Dock Row's node graph, which doesn't match Harrow Yards' different graph) — fixed in the script, not the map; it was never shipped.
- 2026-10-27 · Harrow Yards is proven deliverable (50/50 with Light payload, same bot/logic as the project's balance runner), but Standard/Heavy still fail with that bot — same documented limitation as Dock Row's own balance run (`docs/BALANCE.md`): the greedy bot dithers near a guarded receiver instead of committing, a bot-quality gap, not a map defect. Not re-litigated further here; same open question to the director as Dock Row's.
- 2026-10-27 · Director's call: persist the running match to `localStorage` so a page reload resumes it instead of losing progress. Only the mutable match fields round-trip through JSON (`packages/client/src/persist.ts`); `MatchState.rules` (a `Uint8Array` plus derived lookups) is rebuilt from `content` on restore via the now-exported `buildRuleset(district, balance)`, never serialized. A save that is missing, malformed, the wrong format version, names a district this build doesn't ship, or whose match already ended (`status !== 'play'`) is treated as absent — the app always falls back to a fresh match rather than risk restoring something broken.
- 2026-10-27 · No new test dependency (e.g. jsdom) for the one new client test file that needs `localStorage`: Node has no global `localStorage`, and `persist.ts` only calls three methods on it, so the test stubs a 20-line in-memory `Storage` with `vi.stubGlobal` instead (CLAUDE.md §2: write it yourself when it's this small). `packages/client` had no tests before this; `persist.ts` is the first.
- 2026-10-28 · Procedural district generator (`packages/content/src/mapgen.ts`): room-and-corridor layout on a fixed 16×11 grid, seeded only from `pure-rand`'s `xoroshiro128plus`/`uniformInt` (no `Math.random`, no `Date.now`, per CLAUDE.md §1). Promoted `pure-rand` from `tools/balance`-only to a direct `@wetwire/content` dependency instead of writing a second RNG — same already-approved choice (2026-10-27 Phase 2 entry), reused rather than duplicated. Every generated district is self-checked against the existing `districtSchema` (same reachability/tile/door/node checks hand-authored maps get) before it's accepted; nothing new was added to the schema.
- 2026-10-28 · Director's call: generated maps are saved as real content, not regenerated live per match. `pnpm --filter @wetwire/content gen-maps [count] [baseSeed]` batch-writes accepted candidates to `data/districts/generated/*.json` and rewrites a static barrel (`generated/index.ts`) that `@wetwire/content` always imports (browser-safe — no `fs` read at runtime). This sidesteps a harder trust question (a client picking a seed and asking the server to regenerate a map live, vs. sending map structure over the wire) for now: generated maps become ordinary shared content, loaded identically by client and server like the two hand-authored districts, so §1's "server is the authority" isn't in play yet — there is no per-match live generation. A pruning tool to remove unwanted saved candidates is deferred, per the director; until then every accepted candidate ships and appears in the existing district picker (`Overlays.tsx`, unchanged — it already iterates `content.districts`).
- 2026-10-28 · `content.districts`' exact count is no longer asserted in `packages/content/test/content.test.ts` (it grows as more generated maps are saved); the test instead checks both named hand-authored districts are present and ids are unique.
- 2026-10-28 · Bugfix: `mapgen.ts`'s ICE/camera nodes were placed at `roomCenter.y - 1`, which often landed on a wall tile (looked like "characters spawning in walls" on the Net overlay). Junction nodes may legitimately sit in a wall (pure net abstraction, same as the hand-authored maps); ICE/cameras are physical street objects and now use `openTileInRoom` to guarantee open floor, matching `ironbridge-dock-row.json`'s convention (e.g. `CAM-A` at an open tile).
- 2026-10-28 · `generateDistrict(seed, options?)` takes optional `width`/`height`/`roomCols`/`roomRows` (director's call, in place of picking one fixed bigger size) instead of fixed constants, so `gen-maps` can batch different map sizes without a code change. Generated ids/names only carry a size tag when it differs from the default 16×11, so the already-saved default-size batch keeps its ids. Property-tested up to 40×30 / 6×5 rooms (100 random size combos) against the same `districtSchema`.
- 2026-10-29 · Director's call: added a scouting readout (not in PROMPT.md) ahead of real panning/camera work, prompted by bigger maps not fitting the viewport. `packages/client/src/scouting.ts` reuses the sim's own `distField`/`distAt` (no new rule logic, no client-side guess at reachability) to compute Wren's live distance to the receiver, respecting actual door-lock state. Feeds two UI pieces: a `Route: N` / `Route: cut off` HUD chip, and a small always-on corner minimap (`renderer/minimap.ts`) with dead-end tile shading, expandable to a full-screen overview via a keyboard-accessible button/`V` key (`game.overview`, transient, not persisted). Verified in a real browser (Playwright against the Vite dev server): route chip, corner minimap, and expanded overview all render correctly with no console errors.
- 2026-10-29 · The minimap and dead-end shading show the whole map, every hunter and camera, unconditionally. Safe today because no fog of war exists yet (`viewFor` is still a pass-through, Phase 2/4 architecture — see the 2026-10-27 Phase 4 entry). **Flag for Phase 3:** once fog of war ships, this view needs to be cut down to what the player's own `viewFor` result actually contains, or it becomes a full-map reveal exploit.
- 2026-10-29 · Director's call: first-session progression gate, ahead of the real Phase 5 economy (credits, account level, faction standing — deferred until an expansion actually needs it, since it requires a server-side save, an §1.6 ask). `packages/client/src/progress.ts` tracks a `deliveries` counter in `localStorage` (same pattern as `prefs.ts`/`persist.ts`, no new dependency). A player with zero deliveries sees only the default payload (Standard) and default district (Dock Row) on the start screen (`Overlays.tsx`); every other payload size and every district — including the generated ones — unlocks after the first `delivered` outcome, tracked client-side only, same session, no reload needed. This gates the existing content, it doesn't add or remove anything from a match once started; role selection wasn't included because there isn't one yet (Wren/Kade/Razor are a fixed trio — `roles.json`'s other three kits aren't wired to player choice at all yet, that's separate unbuilt work, not something to gate).
- 2026-10-29 · Map-pruning tool (`packages/content/scripts/prune-maps.ts`), the tool deferred in the 2026-10-28 "generated maps are saved" entry. `pnpm --filter @wetwire/content prune-maps` with no args lists every saved generated map (dims, door/camera/hunter counts) for review; with ids, deletes those and rewrites the barrel; `--all` clears every generated map. Refuses any id not matching `generated-*` (CLAUDE.md §6.7: don't delete files outside what this tool itself writes), so it can't be pointed at a hand-authored district by typo. The barrel-rewrite logic that `generate-maps.ts` already had was pulled into `scripts/mapgen-lib.ts` so both scripts share one source of truth for it, rather than duplicating the rewrite.
- 2026-10-29 · Scripted in-match tutorial (`packages/client/src/tutorial.ts` + `ui/Tutorial.tsx`), per the director: soft hints only (every control stays live underneath, never gated), full coverage of move/sprint/mask/Net-switch/Kade-hack/Razor/run-tick in one pass, skippable at any point. Each step auto-advances either when its specific action is detected (`TutorialStep.match`, reading only existing public `Game` state — no new game-state coupling) or when any tick resolves, whichever comes first, so a player who ignores the hints and just plays is never stuck on a step. Shown once, only on a first-timer's very first match (`progress.ts#showTutorial`); persists `tutorialDone` the moment the tour finishes _or_ the match ends in any outcome (not just Delivered) _or_ Skip is clicked — whichever happens first — so a reload mid-first-match never replays a tour already finished, and a Taken/Flatlined first attempt doesn't re-trigger it on the retry. Highlight ring targets reuse existing CSS classes/attributes (`.dpad`'s mobile-only sibling `.actions`, `.netacts`, `.razoracts`, `.run`, `[data-v="net"]`); added `data-action-type` to Wren's action buttons so Sprint/Mask can be targeted individually. Caught and fixed in review: Preact here does not auto-append `px` to numeric inline-style values (unlike React) — every style value in the highlight ring must be an explicit `${n}px` string, confirmed against this codebase's existing `style={{...}}` usages, which are all strings already.
- 2026-10-27 · Bug found and fixed: the existing Brief button already opened the start screen mid-match, but there was no way back out except Start Run, which silently discarded the in-progress contract. Added Resume (button and Escape) when a match is running, so Brief now works as a real pause menu; Start Run becomes "Restart run" in that state and asks `window.confirm` before discarding progress. Used the native `confirm()` dialog rather than a custom modal — the project has no modal pattern of its own yet beyond the full-screen overlays, and this is a single yes/no gate on a destructive action, not a flow worth a new component for.
- 2026-10-27 · Started wiring the neural budget (§7.2) for real: `WrenState`/`KadeState` gained `loadout: readonly string[]` (equipped implant ids, immutable mid-match), and `createMatch` throws if a starting loadout's slot cost exceeds `balance.neural.capacity` — the sim is the only authority there is without Phase 3's server, so this is the actual rejection point, not a client-only check. `validateLoadout`/`loadoutSlotCost` are exported pure functions for any future picker UI to reuse. `Ruleset` gained `implants: readonly Implant[]` (and `buildRuleset` a third `implants` parameter) so tick steps can see them without needing the whole `Content`.

His dumpshock threshold is now `k.load + loadoutSlotCost(loadout) >= net.loadMax` instead of `k.load` alone, so an implant-heavy Kade dumpshocks sooner for the same amount of hacking. That's §7.2's "chrome is attack surface" line, realized with zero new fields on `KadeState`. Deliberately did **not** add an equivalent runtime meter for Wren this slice: she has no action yet that adds _temporary_ neural load (Mask still charges her existing, separately-tracked `overload`, per the earlier decision not to merge the two), so for her this slice only closes the "rejected above budget at loadout-selection time" half of §9's Phase 4 checklist — attenuation-during-play for her waits until a role action actually costs her load.

Recorded here per CLAUDE.md §5: "If you must change its snapshot, explain exactly which rule changed and why."
- 2026-10-27 · Phase 4 status against §9's checklist, honestly: implants and loadout-budget rejection now work; the other three items (all six roles playable, bot-vs-bot win rates in band) are still not done. Only Courier and Decker have sim mechanics; Razor, Hunter-as-player, Fixer and Receiver remain content-only. That's the next slice, not this one.
- 2026-10-27 · Razor made playable: Strike only this round. Heavy strike's 2-tick wind-up and Guard are real new mechanics on their own (the first wind-up/delayed-effect anything in this sim) and are deliberately deferred rather than bolted on here.
- 2026-10-27 · **New rule invented, not in the spec, flagged rather than silently assumed:** hunters never had a body/health stat before this (Phase 1/2 damage only ever stunned them). Gave them `body: 4` (matching roles.json's Hunter kit, duplicated on purpose — see below) and a `defeated` state: at 0 body a hunter stops patrolling, hunting, attacking and alerting, but stays on the map (no despawn, no respawn timer — §7.5's territory/respawn system is out of scope here). This never ends the match; only the payload's own outcomes do. Same treatment for a downed Razor (`body <= 0`): she can only wait, for the rest of the match, no match-ending consequence either.
- 2026-10-27 · `balance.hunter.body = 4` and `balance.razor = { body: 5, hitDamage: 1 }` intentionally match roles.json's Hunter/Razor `body` values, but are **not derived from them** — they're two independently-recorded numbers in different files for different purposes (role-kit flavour data vs. the sim's actual numbers), so they can drift if one is changed without the other. Flagging the duplication risk rather than silently coupling `packages/sim` to `roles.json`, which is content-only by design.

Before building, pulled **Dead drop** (Courier) back out of scope and flagged it, rather than guess at it: "hand the payload to an adjacent ally" contradicts §2's own premise that a payload is wetwired into the courier's own brain implant, not a physical object, and implementing it properly means a payload-carrier-swap mechanic (who's tracked for delivery, overload and "taken") — a real architectural change, not a kit addition. Shipped Sprint (Courier) and Heavy strike + Guard (Razor) this round; Decker's remaining actions (Lock, Plant ICE, Jack in/out — the last implies Kade needs a street body separate from his Net presence, which he doesn't have), Hunter-as-player, Fixer and Receiver all need their own design-decision round before I can scope them the same way, for the reasons given when this was raised.
- 2026-10-27 · Heavy strike's 2-tick wind-up: commit on tick N (no effect, target locked in, `legalRazorActions` returns only `wait` while winding up — same pattern as a stunned hunter or a dumpshocked Kade), resolves on tick N+1 on its own regardless of what's requested that tick. Fizzles with no damage if the target left range or was already defeated when it resolves — deliberately avoidable by moving away, consistent with this sim's "telegraphed intent, no reflex advantage" pillar (§2), the same spirit as a hunter's own telegraphed step. Not spec-stated; my call, not inferred.
- 2026-10-27 · Guard blocks **one** hit, not every hit that tick, matching "blocks the **next** hit" read literally: `razor.guarding` is consumed (reset to `null`) the instant it blocks something in `stepAttacks`, not just at the start of Razor's next turn. Caught and fixed via my own test (`guard blocks only the first of two simultaneous attackers, not both`) before it shipped — my first draft left it set for the whole tick, which would have let one Guard block two separate hunters attacking Wren and Kade simultaneously.
- 2026-10-27 · A blocked hit still stuns the attacking hunter and still ends its body-mode pursuit of Kade (matches the existing unblocked-hit behaviour exactly) — only the damage is negated. - 2026-10-27 · Sprint gets a keyboard binding (`Shift`+move, +8 overload, same bucket as Mask per the earlier "Wren costs go into her own overload meter" decision); Heavy strike and Guard stay buttons-only like Strike already was — they need a target, which doesn't map cleanly onto a single keypress, and Razor's whole kit was already established as click-only in the previous slice.

## Phase 1

- 2026-10-27 · Sim and client live in one `index.html`, split into `<script id="sim">` (pure, exposes `Sim`) and `<script id="client">`. · Phase 1 must be one file; the split lets `tests/phase1.test.mjs` load the sim in Node via `vm` with no build step, and keeps the Phase 2 extraction into `packages/sim` mechanical.
- 2026-10-27 · Tests use built-in `node:test` (`node --test tests/phase1.test.mjs`), not Vitest/fast-check. · Phase 1 has no package manager or dependencies; property tests use a seeded LCG. Switch to Vitest and fast-check in Phase 2.
- 2026-10-27 · All tunables in `CONFIG` at the top of the sim script. · CLAUDE.md "no magic numbers"; becomes `packages/content` in Phase 2.
- 2026-10-27 · Hunter first waypoints: H-1 heads for (13,1) first, then (2,1). H-2 starts with waypoint index 1, i.e. (9,3), as specified. · Spec gives H-1's endpoints but not its first target.
- 2026-10-27 · Hunters may share a tile; "blocked" means the planned tile is no longer passable. · Simplest option that keeps the telegraph promise.
- 2026-10-27 · "Adjacent" for hunter sight and attacks is Manhattan distance ≤ 1 (no diagonals). · Matches the attack rule in §3.6 step 6 and 4-neighbour movement.
- 2026-10-27 · Stunned hunters do not see Wren. Hunters in _body_ mode ignore camera alerts and sight (they keep heading for Kade's body). · §3.6 step 4 exempts body-mode hunters from alerts; sight is treated the same so the two rules agree.
- 2026-10-27 · A camera that sees Wren counts one alert and logs one event per camera per tick. · "Camera alerts" stat needs a definition.
- 2026-10-27 · End-state priority when several happen in one tick: Delivered, then Taken, then Flatlined (order of §3.6 step 8). · The read-out completing is the contract being fulfilled.
- 2026-10-27 · Recovery stun and burn stun are both set to 2 and decremented in step 7 of the same tick, so a hit-recovery stun costs the hunter exactly one further move, while a burn (applied in step 1) costs two. · Literal reading of §3.6 order; flagged for review in case recovery should also be two full ticks.
- 2026-10-27 · Kade hit by a hunter: load is raised to 70 in step 6, then decays by 6 in step 7 (no hack that tick), ending at 64. · Literal reading of §3.6 order.
- 2026-10-27 · Kade's legal Burn targets only hunters with no stun left. · Avoids wasting load on a no-op.
- 2026-10-27 · Net layer is not rendered while the wipe is fully on Street. · Skips a full offscreen pass with no visible effect; both layers render whenever the wipe is moving.
- 2026-10-27 · Chromatic offset on overload > 75 % is a double-draw offset at 60 % alpha, not a true channel split. · Cheap, readable; honours `prefers-reduced-motion`.
- 2026-10-27 · Hunter vision tiles, camera cones and legal action lists are cached per state change. · CLAUDE.md: no per-frame allocation in the render loop.
- 2026-10-27 · No third-party libraries in Phase 1; the §2 GitHub/npm search was NOT done. · Phase 1 is a single dependency-free file and BFS plus a Bresenham line of sight are about 40 lines, but the search is still owed before Phase 2 (pathfinding/FOV helpers, Zod, PixiJS, Preact, Colyseus).

## Phase 2

Library choices (CLAUDE.md §2). Data pulled from the npm registry and GitHub API on 2026-10-27: licence, last release, stars, open issues, install scripts (none in any pick).

- 2026-10-27 · **pixi.js 8.22** for rendering, **pixi-filters 6.1** for the glow and RGB-split filters (per-filter subpath imports). · Spec names Pixi v8. Alternatives: phaser 4.2 (a whole framework with its own loop and scenes, which fights a pure sim). MIT, 48.5k stars, pushed the day before. Structure and rules:

- 2026-10-27 · `packages/content` holds the district and every balance number as JSON, parsed by Zod. The Phase 1 `CONFIG.cam.blindTicks` and `CONFIG.net.blindTicks` duplicate is merged into `net.blindTicks`; `net.bodyThreatRange` (4) is new and only drives the "body under threat" chip and PiP alert, which previously reused `burnRange`. - 2026-10-27 · `MatchState` carries a shared, never-cloned `rules` table (district, balance, wall and door grids, node lookups). `resolveTick` copies only what changes during a tick and returns a new state; the input is untouched (tested).
- 2026-10-27 · `viewFor(state, player)` returns the whole state in Phase 2. · Nothing is hidden in single-player. Phase 3 narrows it, and CLAUDE.md §7 requires a leak test per role at that point.
- 2026-10-27 · Bots live in `tools/balance/src/bots.ts` and only use the sim's public API. Bot randomness comes from pure-rand seeded per match.
- 2026-10-27 · `erasableSyntaxOnly` is on, so Node can run the sim, content and tools directly (`--experimental-strip-types`) with no build step. Consequence: no enums or constructor parameter properties.
- 2026-10-27 · Pixi layers: static art is retained `Graphics`; anything that depends on state, plan or view is rebuilt only when `game.version` changes; per-frame work is limited to transforms and alphas. The Net marching-ants links, target brackets and plan beam are redrawn at about 12 Hz while the Net is visible. · Keeps the render loop free of per-frame allocation as far as practical.
- 2026-10-27 · The PiP inset is a Pixi `RenderTexture` of the street layer, cropped around Kade's body, drawn only while the Net is at least half visible.
- 2026-10-27 · The Phase 1 chromatic jitter is now an RGB-split filter on the street layer for 120 ms every 4 s while overload is above 75 %. `Motion: system / reduced / full` is a user preference that overrides `prefers-reduced-motion`.
- 2026-10-27 · Rain is a scrolling tiling sprite of one small pre-generated streak texture, not 140 individual particles.
- 2026-10-30 · UX fix: breaking the last ICE layer doesn't open whatever it was guarding — Kade still has to route onto the ICE node first, one hop away from where the hack was cast. That extra step wasn't telegraphed, so a broken-but-uncrossed ICE node now gets a "CLEAR — ROUTE THROUGH" label and the same target brackets a hack gets, in `packages/client/src/renderer/net.ts`, until Kade actually steps onto it.
- 2026-10-30 · Desktop layout now fills the viewport instead of capping at `max-width: 1560px` with page-level scroll. Above the existing 1100px stacking breakpoint, `#app` (the real parent of `.top`/`.layout` — not `body`, see `index.html`) becomes a `height: 100vh` flex column; `.layout`'s three panels each scroll independently (`overflow-y: auto`) instead of the whole page scrolling. `.stage` drops its width-driven `aspect-ratio` in that mode (`flex: 1 1 0` instead, sized purely from leftover space) and the canvas gets `object-fit: contain`, so the map letterboxes to whatever space is left — vertically on short/wide windows, horizontally on tall/narrow ones — without distorting or overflowing. Below 1100px (and on initial/mobile layout) nothing changed: the page scrolls normally, same as before.
